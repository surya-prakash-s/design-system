## 2024-10-24 - Support Complex Screen-Reader Labels in Buttons and Fix Boolean/String PropType Mismatches
**Learning:** Primitives like ButtonIcon frequently receive complex nodes/elements as label or assistive text parameters, and standardizing their PropType validation to allow both string and node types prevents rendering failures and warnings. Similarly, boolean props must consistently support shorthand boolean invocation rather than string literals, and stateful toggles like `aria-pressed` should accept both string and boolean configurations to align with standard HTML/JSX patterns.
**Action:** Always declare assistive text props with `PropTypes.oneOfType([PropTypes.string, PropTypes.node])` to support complex layouts, validate ARIA properties to accept both bool and string formats, and use JSX boolean shorthand notation in place of string equivalents.
